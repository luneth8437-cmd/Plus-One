# Plus One 优化交付与上线边界

## 产品规则

保留原 Django 页面、匿名一对一和现有视觉风格。新匹配先等待，最多 10 分钟且不超过卡片有效期；双方聊天页最近 15 秒都发送过前台信号时开始五分钟聊天。开始后不暂停、不重置。近期在线只是近似信号，不是绝对实时在线承诺。

等待期间占用名额，但不能发消息、同意见面或生成 AI 建议。允许退出和举报。等待/聊天结束释放仍有效的卡片；已取消卡片不复活，同一参与者与同一卡片的旧匹配不能重新启动。

激活只写一条规则破冰消息，不请求外部 AI。AI 草稿/建议仍由用户主动发起。审核不可用时暂停发布/发送并保留输入；浏览、退出、举报不依赖 AI。

发布者重置身份会先设置退休标记，阻止旧页面的在途写入，然后取消未完成卡片、关闭其等待/聊天。参与者重置释放其匹配；已同意的见面历史保留。第三方与已退休身份不能激活/推进旧匹配。

## 可靠性与成本

- 发布和聊天消息必须携带 UUID。历史行保持 NULL；不为旧数据虚构请求 ID。同 ID 同内容返回原结果，不重复保存或计数；不同内容返回 409。发消息的成功结果在聊天结束后仍能重放。
- 所有运行时消息（含系统消息）与状态转换采用同一锁顺序：参与者用户按 ID、活动卡、匹配。外部审核在锁外，回到锁内再检查当前状态。
- 轮询位置与已显示消息分离；客户端按服务端 ID 排序去重，只用轮询响应单调推进位置。
- 数据库限流跨进程共享。AI 草稿/建议 6 次/分钟，发布与编辑 10 次/小时，消息 30 条/分钟；固定时间窗口，429 返回 Retry-After。同一 UUID 在窗口内不重复占用额度。
- 原始输入/活动描述 2,000 字符，消息/举报说明 500 字符。外部 AI 不自动重试；审核总预算 5 秒，解析/建议 8 秒。取消会传递给异步 HTTP 客户端并关闭连接，不留下后台线程继续调用。

## 举报、清理和统计

举报独立于匹配结果，每个参与者/匹配一份，可修改说明。等待/聊天举报结束会话；结束或见面后举报不重写历史。已处理举报再次提交会回到待处理，保留原处理备注。管理后台标出超过七天未处理的记录。

活跃时间只由正常访问/用户动作更新，每五分钟最多写一次；后台轮询、保活、presence 不刷新身份寿命。旧身份 last_seen_at 保持 NULL，回退使用原登录/创建时间。

默认保留窗口为不活跃身份 7 天、AI 日志 30 天、事件 90 天。有效卡片、等待/聊天、未来约会和预计结束后 24 小时保护双方；近 90 天未处理举报保护双方身份。举报记录按首次创建计算最多 90 天；补充不延长这个时钟，逾期补充返回 410。终态聊天证据按消息创建时间最多 90 天，新举报不能延长旧证据；仍在进行/未来约会的业务保护优先。

新建或编辑活动可填写预计结束时间；留空时采用开始后一小时。旧数据保持 `NULL`，继续按开始时间计算 24 小时保护，不为历史记录虚构结束时间。

清理默认 dry-run。用户逐个锁定并重查，独立记录分批。`--batch-size` 限制选中的身份/各类独立记录数；删除一个身份会级联其归属记录，不能将该参数误解为严格的所有数据库行上限。生产先用小批量预演评估关联记录，再安排定时执行。过期但尚未完成状态转换的 LIVE 匹配仍受保护；先运行 `expire_records` 再清理。没有公开删除接口，也没有启用自动清理。

创建、编辑、匹配、聊天开始、双方同意和见面确认分开统计。事件保留独立活动/匹配引用和创建时间，业务记录删除后仍可归因；报表统一按活动创建 cohort 分组。无法恢复的历史归因保留未知，旧的已同意见面但无对应事件单独列出，不伪造历史事件。自报见面仍不等于独立验证的实际到场。

## 迁移与上线顺序

1. 在隔离测试库确认 0009 → 最新迁移，旧聊天的状态/截止时间不改；保留旧用户、卡片和消息。
2. 上线前导出备份，并在独立空库验证恢复。此项生产验证尚未执行。
3. 先在部署环境设置 `PLUSONE_NEW_MATCHES_ENABLED=false`，发布全部兼容服务端和增量迁移，确认 `/readyz/`。此开关只停止新建匹配，保留理解 WAITING 的服务端和旧会话。
4. 更新静态资源和表单，确认严格请求 ID 正常，再开启新匹配。存留的旧页面会提示刷新，不能静默重复创建。
5. 失败时关闭新匹配入口并保留数据；不要回退到不认识 WAITING 的旧程序，也不要反向删除新字段。

本地迁移/回归通过不等于线上已部署；提交、推送、托管平台构建和线上数据库升级必须分别确认。

## 复验

```sh
python -m pip install -r requirements.txt
python -m pip check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test plusone --noinput
npm ci
npm run test:js
npx playwright install chromium
npm run test:browser
```

分别指定隔离 SQLite / PostgreSQL `DATABASE_URL`，清空真实 AI 密钥；测试用 mock 或明确的开发规则模式。CI 矩阵同时测试两类数据库。Playwright 只对本地测试站点写入。

浏览器套件默认新建临时 SQLite，不继承普通 `DATABASE_URL`。需要 PostgreSQL 时，显式设置 `PLUSONE_E2E_DATABASE_URL`，只接受 localhost/127.0.0.1 且库名以 `_ci` 或 `_e2e` 结尾的专用测试库；拒绝远程/普通业务库。`PYTHON` 可指定已安装依赖的解释器。
